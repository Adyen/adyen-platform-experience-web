# i18n Patterns

All user-facing text must use the internationalization system. Never hardcode strings.

## Getting i18n

Vue 3 components get the i18n instance from the core context:

```vue
<script setup lang="ts">
import { useCoreContext } from '@integration-components/core/vue';

const { i18n } = useCoreContext();
</script>

<template>
    <span v-text="i18n.get('transactions.overview.title')" />
</template>
```

## Translation Methods

### `i18n.get(key, options?)` - Basic Text

```typescript
// Simple key
i18n.get('transactions.overview.title');
// → "Transactions"

// With interpolation
i18n.get('transactions.overview.export.columns.all', { values: { count: 12 } });
// → "All 12 columns"

// With count-based plural selection
i18n.get('payByLink.creation.validity.linkValidityUnit.day', { values: { quantity: 1 }, count: 1 });
// → "1 day"
i18n.get('payByLink.creation.validity.linkValidityUnit.day', { values: { quantity: 5 }, count: 5 });
// → "5 days"
```

When no translation exists for a key (after the plural and exact-count lookups), `get()` returns the key string itself, so missing keys surface directly in the UI.

### `i18n.amount(value, currencyCode, options?)` - Currency

```typescript
// Basic amount (value in minor units)
i18n.amount(1234, 'EUR');
// → "€12.34"

i18n.amount(100000, 'USD');
// → "$1,000.00"

// Currencies without decimals
i18n.amount(1234, 'JPY');
// → "¥1,234"

// Negative amounts
i18n.amount(-5000, 'EUR');
// → "- €50.00"

// Hide currency symbol
i18n.amount(1234, 'EUR', { hideCurrency: true });
// → "12.34"
```

### `i18n.date(date, options?)` - Date Formatting

```typescript
// Basic date (defaults: numeric year, 2-digit month and day)
i18n.date('2024-01-15T10:30:00Z');
// → "01/15/2024" (en-US, UTC)

// With custom options (merged over the defaults)
i18n.date('2024-01-15T10:30:00Z', { month: 'long', year: 'numeric' });
// → "January 15, 2024" (en-US, UTC)
```

The formatted value also depends on the active timezone (see Timezone-Aware Date Formatting below).

### `i18n.fullDate(date)` - Date with Time

```typescript
i18n.fullDate('2024-01-15T10:30:00Z');
// → "Jan 15, 2024, 10:30:00" (en-US, UTC)
```

### `i18n.has(key, options?)` - Check Key Exists

Returns `true` when a translation exists for the key, applying the same count-based lookup as `get()`:

```vue
<h2 v-if="i18n.has('capital.common.contactSupport.reachOut')" v-text="i18n.get('capital.common.contactSupport.reachOut')" />
```

## Translation Files

Translation keys live in JSON catalogs:

- **Source of truth**: `packages/domains/<domain>/vue/translations/en-US.json`, one catalog per domain (capital, disputes, payByLink, payouts, reports, transactions); every key is prefixed with its domain name
- **Merged catalog (generated)**: `packages/sdk/translations/en-US.json`, the union of all domain catalogs; do not edit it by hand
- **Bento mirror (generated)**: `packages/sdk/translations/bento/en-US.json`
- **Types**: `TranslationKey` is the key union derived from the merged catalog

### Adding New Keys

1. Add keys to the domain catalog at `packages/domains/<domain>/vue/translations/en-US.json`, following the existing style:

```json
{
    "transactions.overview.export.buttonLabel": "Export",
    "transactions.overview.export.columns.title": "Columns",
    "transactions.overview.export.cancel": "Cancel"
}
```

2. Run `pnpm run translations:sync` (also enforced by the pre-commit hook) to regenerate `packages/sdk/translations/` and `packages/sdk/translations/bento/`. Keep catalogs sorted with `pnpm run translations:sort`.

3. Once the merged catalog is regenerated, the new keys become part of the `TranslationKey` union.

### Key Naming Convention

```
{domain}.{section}.{element}

Examples:
transactions.overview.title
transactions.overview.filters.amount
payByLink.creation.amount.label
capital.offer.summary.requestFundsWithAmount
```

## Interpolation

Placeholders use the `%{name}` syntax.

### Simple Values

```json
{ "capital.common.values.numberOfDays": "%{days} days" }
```

```typescript
i18n.get('capital.common.values.numberOfDays', { values: { days: 5 } });
// → "5 days"
```

### Multiple Values

```json
{ "capital.overview.grants.repaymentRatio": "%{repaidAmount} of %{totalAmount} repaid" }
```

```typescript
i18n.get('capital.overview.grants.repaymentRatio', {
    values: {
        repaidAmount: i18n.amount(10000, 'EUR'),
        totalAmount: i18n.amount(25000, 'EUR'),
    },
});
// → "€100.00 of €250.00 repaid"
```

`values` can also be a function `(placeholder, index, repetitionIndex) => value` when each placeholder occurrence needs custom handling.

### Rich Text / HTML Markup

**Never** use `i18n.get()` or `v-html` to inject markup into translation placeholders. Compose translated fragments with safe Vue template nodes so text remains translatable without interpreting HTML.

Catalogs use a `%{break}` placeholder for line breaks: the component passes a real separator via `values` (for example `values: { break: '\n' }`, as in `capital.offer.legalNotice.US.title`) and renders the resulting fragments as separate text nodes. Prefer complete translated sentences. When styling a fragment is unavoidable, use Vue template bindings and dedicated translation keys rather than inserting raw HTML.

## Pluralization

Count-based variants use `__` suffixes. The family of a key is:

- `key__0` - exact form for count 0
- `key__1` - exact form for count 1
- `key__plural` - the greater-than-one form
- `key__N` - exact form for an integer N ≥ 2 (for example `key__5`)

With `options.count`, the lookup order is:

1. `key__{count}` (exact count match)
2. `key__plural` (only when `count` is greater than 1)
3. the base `key`

`count` defaults to `0`, so a `key__0` variant also applies when `get()` is called without options. The current catalogs only ship base and `__plural` forms.

```json
{
    "payByLink.creation.validity.linkValidityUnit.day": "%{quantity} day",
    "payByLink.creation.validity.linkValidityUnit.day__plural": "%{quantity} days"
}
```

```typescript
i18n.get('payByLink.creation.validity.linkValidityUnit.day', { values: { quantity: 1 }, count: 1 }); // → "1 day"
i18n.get('payByLink.creation.validity.linkValidityUnit.day', { values: { quantity: 5 }, count: 5 }); // → "5 days"
```

## Common Patterns

### Timezone-Aware Date Formatting

When displaying dates that should respect a specific timezone (e.g. a balance account's timezone), use the `useTimezoneAwareDateFormatting` hook instead of calling `i18n.date()` or `i18n.fullDate()` directly. The hook passes the timezone to each formatting call as an option, without mutating the i18n instance, so timezones cannot leak between calls. When the provided timezone is missing or invalid, it falls back to the instance's current `i18n.timezone`.

```typescript
import { useTimezoneAwareDateFormatting } from '@integration-components/composables-vue';

const { dateFormat } = useTimezoneAwareDateFormatting(() => props.activeBalanceAccount?.timeZone);

dateFormat('2024-01-15T10:30:00Z');
// → "01/15/2024" (in the balance account's timezone)
```

### Labels and Placeholders

```vue
<BentoDropdown
    :label="i18n.get('payByLink.creation.validity.label')"
    :placeholder="i18n.get('payByLink.creation.select')"
/>
```

### Error Messages

```vue
<BentoInputField
    :label="i18n.get('payByLink.creation.amount.label')"
    :error-message="i18n.get('transactions.overview.export.errors.download')"
/>
```

### Button Text

```typescript
import type { BentoButtonActionsList } from '@adyen/bento-vue3';

const actions: BentoButtonActionsList = [
    { title: i18n.get('transactions.overview.export.buttonLabel'), event: handleExport },
    { title: i18n.get('transactions.overview.export.cancel'), event: dismissPopover },
];
```

### Table Headers

```typescript
const columns = [
    { field: 'createdAt', label: i18n.get('transactions.overview.export.columns.createdAt') },
    { field: 'netAmount', label: i18n.get('transactions.overview.export.columns.netAmount') },
];
```

### Empty States

```typescript
const emptyState = {
    title: i18n.get('transactions.overview.errors.listEmpty'),
    description: i18n.get('transactions.common.errors.updateFilters'),
};
```

## Testing with Custom Translations

In stories, override translations through `coreOptions`. Locale keys use the canonical `'en-US'` format (`formatLocale` also normalizes underscore variants such as `'en_US'`):

```typescript
export const CustomLabels: ElementStory<typeof Component> = {
    args: {
        coreOptions: {
            translations: {
                'en-US': {
                    'transactions.overview.title': 'Custom Title',
                },
            },
        },
    },
};
```

## Checklist

- [ ] All user-visible text uses `i18n.get()`
- [ ] All amounts use `i18n.amount()`
- [ ] All dates use `i18n.date()` or `i18n.fullDate()` (or `useTimezoneAwareDateFormatting` when a timezone applies)
- [ ] Keys follow naming convention
- [ ] Placeholders use `%{name}` syntax
- [ ] Pluralization uses `__plural` (plus `__0`, `__1`, or `__N` count variants when needed)
- [ ] New keys added to `packages/domains/<domain>/vue/translations/en-US.json`
